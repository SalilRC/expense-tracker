# Data Model: CSV Expense Import and Export

## Entity: Expense

The existing persisted expense record; CSV import creates new instances and export reads the current collection.

### Fields

- **id**: string
  - Unique within the expense collection.
  - Generated by the app for every imported record; not present in the CSV interchange columns.
- **date**: string
  - Required ISO calendar date in `YYYY-MM-DD` format.
- **description**: string
  - Required non-empty text after trimming surrounding whitespace.
- **category**: string
  - Required value after trimming surrounding whitespace; it must match Groceries, Fuel, Travel, Eating Out, Utilities, or Other exactly and case-sensitively.
- **amount**: number
  - Required positive finite number no greater than `100000` before normalization to two decimal places.
  - Import accepts one or more digits optionally followed by a decimal point and one or more digits; signs, exponent notation, currency symbols, and thousands separators are invalid.
  - Decimal half-cent ties round up; values rounding to zero or exceeding the maximum before rounding are invalid.

### Relationships and State

- Imported expenses are appended to the existing expense collection; import never replaces existing records.
- The collection is persisted to localStorage through the existing save path.
- Category totals and the grand total are derived from the current collection and refreshed after a successful import.

## Entity: CSV Expense File

A UTF-8 CSV document with one header record and zero or more expense data records.

### Fields

- Required headers: exactly one case-sensitive occurrence of `date`, `description`, `category`, and `amount`; their order may vary, and header whitespace is not trimmed.
- A leading UTF-8 BOM is ignored when matching the first header.
- Imports are UTF-8 and accept CRLF or LF record separators; exports are UTF-8 with BOM and CRLF separators.
- Export writes headers in `date`, `description`, `category`, `amount` order.
- Exported amount cells are plain numeric text with exactly two decimal places and no currency symbol.
- Additional import headers are permitted and ignored; required headers must occur exactly once.
- Quoted fields may contain commas, quotes (escaped by doubling), and line breaks.

## Entity: Import Result

Represents one selected file's processing outcome.

### Fields

- **acceptedCount**: non-negative integer; number of valid records appended.
- **skippedCount**: non-negative integer; number of nonblank, structurally parseable data records rejected by row validation.
- **skippedReasons**: list of user-readable explanations; each entry identifies its CSV record number and validation reason.
- **fileError**: optional user-readable file-level error. When present, the collection is unchanged and row counts are not presented as a partial import result.

### Processing Rules

- Malformed CSV syntax or missing/duplicate required headers is a file-level error and causes no mutation.
- A row with a field count different from the header, or an expense field failing validation, is skipped without blocking other valid rows.
- Completely blank records are ignored and are not included in either count.
- Every skipped nonblank record includes its record number and specific reason in import feedback.
- A header-only file returns zero accepted and zero skipped records; a zero-byte file returns a file-level error.
- Successful accepted records are staged, assigned unique IDs, appended together, persisted, and rendered once.
- If localStorage persistence fails, the import is not committed to the in-memory collection and a user-readable error is returned.
